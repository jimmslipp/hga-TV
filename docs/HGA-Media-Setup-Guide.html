1 · What you've been given

A complete, finished Android app called HGA-Media. It is a working IPTV player in the mould of IPTV Smarters Pro, with an advertising engine built into it. It ships with no channels — you point it at your own Xtream Codes line or M3U playlist.

Straight answer on your quarter-panel idea

You said it would be very difficult. It isn't — it's built and it's the default. When an advert break comes, the live picture shrinks smoothly into the top-left three quarters of the screen and your advert fills the L-shape that opens up down the right and along the bottom. The sound carries on. Nothing is covered. Nobody misses a goal. It's the same trick Sky and ITV use during racing.

You also have two other modes and can switch between all three from the remote at any time, per venue, without rebuilding anything.

2 · Getting the app built into an APK

An app's source code has to be "built" into an installable .apk file. Normally that means installing developer software. You don't have to — GitHub will build it for you, free, in a web browser.

One thing to know before you start

This step needs a computer (Windows or Mac), not a phone, because you have to drag a folder into a web page. It takes about ten minutes and you only ever do it once. Everything after this can be done from your phone.

  1. Unzip the folder Unzip HGA-Media.zip somewhere you can find it, like your Desktop. You should end up with a folder called HGA-Media containing app, docs, gradlew and a few other bits.
  2. Make a free GitHub account Go to github.com/signup. Any email, any username. It's free and you never have to pay for what we're doing.
  3. Create a new repository Click the + at the top right → New repository. Name it hga-media. Set it to Private. Do not tick "Add a README". Click Create repository.
  4. Upload the project On the next page click uploading an existing file. Open your HGA-Media folder, select everything inside it, and drag it onto the web page. Wait for the files to finish uploading — there are a few hundred, so give it a minute. Then click Commit changes.

    Important: drag the contents of the folder, not the folder itself.
  5. Let GitHub build it Click the Actions tab along the top. You'll see a job called Build HGA-Media APK, probably already running. If it isn't, click it on the left, then Run workflow → Run workflow.

    Wait 4–8 minutes. A green tick means it worked.
  6. Download your APK Click into the finished run. Scroll to the bottom to Artifacts and download HGA-Media-APK. Unzip it and you have HGA-Media.apk — your app.
Every time you want a change

Change a file on GitHub (or ask me to), and GitHub rebuilds the APK automatically. You just download the new one. You never install a single piece of developer software.

3 · Installing it on your TV box

Fire TV Stick / Fire TV — the easy way

  1. Allow app installs On the Fire Stick: Settings → My Fire TV → Developer Options → turn on Apps from Unknown Sources (on newer sticks it's Install unknown apps, and you allow the Downloader app specifically).

    If you can't see Developer Options: go to Settings → My Fire TV → About and click on the device name seven times.
  2. Install Downloader Search the Fire TV app store for Downloader (the orange one by AFTVnews). Install it.
  3. Put the APK somewhere it can be fetched Upload HGA-Media.apk to Dropbox, Google Drive, or your own website, and get a direct download link. Shorten it at tinyurl.com so it's easy to type on a remote.
  4. Type the link into Downloader Open Downloader, type the short link, press Go. It downloads, then asks if you want to install. Say yes.
  5. Done HGA-Media appears in your apps. Long-press it to move it to the front row.

Android TV boxes / Google TV

Same idea. Turn on Settings → Apps → Security & restrictions → Unknown sources, then use Downloader, or the Send files to TV app, or plug in a USB stick with the APK on it and open it with a file manager.

Phones and tablets

Email yourself the APK, tap it, allow installing from that app when prompted. The same single APK works on phones, tablets, TV boxes and TVs.

How the app gets your adverts

The app looks for a small text file called ads.json that lists your adverts and where the picture files are. It checks two places, in order:

  1. Primary — a machine on your own network, in the venue. Fast, works with no internet.
  2. Fallback — an address on the web. Used whenever the primary can't be reached, or for screens at other sites.

Whatever it finds, it downloads and keeps on the device. If both go down, the adverts already on the screen keep running. A venue with a dead broadband line still shows your advertising.

Setting up the web fallback (do this first — it's the easy one)

Use GitHub again, since you already have an account.

  1. New repository, public this time Call it hga-adverts. Set it to Public (it needs to be, for the TVs to read it). Tick "Add a README".
  2. Upload your adverts Click Add file → Upload files. Drag in ads.json and all your advert images from docs/advert-pack/. Commit.
  3. Switch on GitHub Pages Settings → Pages. Under "Branch" choose main and / (root). Save. Wait two minutes.
  4. Your address It'll be https://YOURNAME.github.io/hga-adverts/ads.json. Open it in a browser to check it loads.
  5. Put it in the app Owner console → Fallback source (web) → paste that address. Then Sync now. It should say how many adverts it found.

Give the machine a fixed address

Whatever you use, set a static IP for it in your router, or the address will change one day and every TV will quietly fall back to the web copy.

The advert list, explained

Open docs/advert-pack/ads.json in Notepad. It looks like this:

{
  "version": 1,
  "settings": {
    "mode": "lbar",
    "intervalSeconds": 600,
    "displaySeconds": 20,
    "showOnChannelChange": true
  },
  "ads": [
    {
      "id": "hga-arcade-01",
      "name": "Hooked Gaming Arcade",
      "url": "example-fullscreen.jpg",
      "lbarUrl": "example-lbar.png",
      "durationSeconds": 20,
      "weight": 3
    }
  ]
}
SettingWhat it does
versionBump this by 1 whenever you change anything. Not essential, but it makes the logs readable.
modelbar, overlay, interstitial or off. This overrides what's set on the TV, so you can change every screen you own from one file.
intervalSecondsSeconds of viewing between advert breaks. 600 = every 10 minutes.
displaySecondsHow long an advert stays up.
showOnChannelChangeAlso show a full-screen advert when someone changes channel.
quietStart
quietEnd		e.g. "23:00" and "08:00" — no adverts at all in that window.

Each advert

FieldWhat it does
idAny unique short name. Used for the play counts.
nameWhat you'll see in the reports.
urlThe picture (or video) file. Just the filename if it sits next to ads.json.
lbarUrlOptional. A purpose-made L-shaped image. See the next section — this is what makes it look properly professional.
durationSecondsHow long this particular advert shows.
weightHow often it comes up. An advert with weight 3 appears three times as often as one with weight 1. Charge more for a higher weight.
startDate
endDate		"2026-06-01" — a campaign that starts and stops on its own.
daysOfWeek[1,2,3,4,5] = Monday to Friday. 1 is Monday, 7 is Sunday.
startTime
endTime		"16:30" to "19:30" — happy hour adverts that only run at happy hour.
To add a new advert

Upload the image to your hga-adverts repository, add a block to ads.json, commit. Every screen picks it up within the hour — or immediately if you press Sync now on the TV. You never touch the app.

The L-bar template — the one that matters

The chequered area must stay fully transparent — that's where the TV shows through.

Design your advert into the grey L on the right and along the bottom. Leave the big rectangle completely transparent. Export as a PNG (not JPG — JPG can't do transparency). Put that filename in lbarUrl.

Here's the worked example that ships with the pack:

example-lbar.png — ready to use, or a starting point for your own.

If you can't be bothered with the L template

Skip lbarUrl entirely. The app will take your ordinary rectangular advert and letterbox it neatly into both arms of the L. It won't be stretched or cropped — it just won't look as designed as a purpose-made one. Perfectly fine to start with.

Video adverts

Supported in overlay and between-channel modes. MP4, H.264, 1920×1080, under about 20 MB. Set "type": "video". Video adverts don't play in L-bar mode — running two videos at once is more than a Fire Stick can comfortably manage, so L-bar sticks to images and stays smooth.

About "Start on power up"

This works on most Fire TV and Android TV boxes. On some newer Android versions Google blocks apps from launching themselves after a reboot. If you find a box that won't do it, the reliable fix is a £3 app like "Launch on Boot" from the store, or setting HGA-Media as the device's home screen. Tell me which box and I'll give you the exact steps for it.

Proving impressions to an advertiser

Owner console → Reporting → Play counts. Every advert, with the number of times it has played on that screen since the last reset. Multiply by your typical footfall and you have a rate card.

9 · When something goes wrong

SymptomFix
Channel won't startThe app retries three times on its own. If it still fails, your line is probably at its connection limit — check no one else is watching on the same details.
Picture keeps stutteringSettings → Buffer size → High (60s). Weak wifi is almost always the cause.
All channels failSettings → Stream format → switch between .ts and HLS, then Refresh playlist. Some providers only serve one properly.
No TV guideSettings → Guide status. If it says Not loaded, your provider's guide is slow — it loads in the background and appears within a few minutes.
Adverts not showingOwner console → Sync now. Read the message it gives you — it says exactly which source answered and how many adverts it found.
"No advert source configured"You haven't pasted an address into Primary or Fallback yet.
Adverts stopped overnightCheck Quiet hours in the owner console.
Forgot the PINClear the app's data in the device settings. That resets it to 4321 and you re-enter your playlist.
The GitHub build went redClick into it, copy the red error text, send it to me. Usually a file that didn't upload.

10 · The Play Store route

You chose to sideload first, which is right — you can have this running in a venue this week. When you want it in the Play Store:

  1. Pay Google's one-off £20-ish developer fee at play.google.com/console.
  2. The app needs a signed release build rather than the test build you're using. That's a change to the build file and one secret key — ask me and I'll set it up.
  3. You'll need a privacy policy at a public web address. A short one is fine; I can write it.
  4. Expect questions. Google approves IPTV players that ship with no channels — which is exactly what this is — but reviewers are twitchy about the category. Be clear in the listing that it's a player for content the user already subscribes to. Budget two to four weeks and possibly one rejection.

Honestly? For arcade and venue screens the Play Store buys you very little. It matters if you want customers installing it on their own devices. If it's your own screens, sideloading is simpler and you keep full control of updates.

11 · What I'd do next

Things deliberately left out of version one, in the order I'd add them:

  • Advert reporting back to you. Right now play counts live on each TV. A small web endpoint would let every screen phone home, so you get one dashboard across all sites — and a printable report for advertisers.
  • Recording / catch-up. The app already reads the archive flag from your provider; playing it back is the next step.
  • Multiple playlists. One profile per screen today; a picker would let one box switch between lines.
  • Full-screen TV guide grid. There's a per-channel guide now; the classic scrolling grid is a bigger job.
  • Remote management. Change a venue's advert mode from your phone without walking to the TV.
